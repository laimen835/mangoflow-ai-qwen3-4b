# MangoFlow AI — Qwen3 4B

Полные исходники существующей программы для передачи разработчику и дальнейшей доработки.
Python/FastAPI, PostgreSQL/pgvector, Ollama и статический веб-интерфейс.
Это самостоятельный репозиторий с основной веткой main; старой истории с приватными
настройками здесь нет. Исходная версия приложения: c438abb; результаты проверки моделей
и 60 регрессионных вопросов сохранены вместе с кодом.

## Состав

- `src/` — API, чат, поиск/RAG, модели БД, парсинг документов, crawler и ограниченный гостевой шлюз.
- `widget/` — весь интерфейс, JavaScript/CSS и логотип; отдельная сборка npm не требуется.
- `migrations/`, `alembic.ini` — схема и миграции PostgreSQL.
- `requirements*.txt` — закреплённые зависимости; `docker-compose.yml` — локальная БД.
- `scripts/` — загрузка/индексация, проверки качества и вспомогательные инструменты.
- `tests/` — тесты и регрессионные вопросы, включая сравнение моделей.
- `docs/` — архитектурные решения, отчёты, ограничения и передача разработчику.
- `.env.example`, `model-version.json`, `Modelfile.qwen3-4b` — безопасный пример настроек и точная идентификация LLM.

## Для разработчика

Начать с [памятки передачи](docs/DEVELOPER-HANDOFF.md), затем ARCHITECTURE.md,
KNOWN_ISSUES.md и [сравнения моделей](docs/APPLICANT-MODEL-COMPARISON-20261117.md).
Старые абсолютные пути в исторических документах относятся к компьютеру владельца,
не являются обязательными путями новой установки. Работать в текущем clone.

## Запуск на новой машине

Нужны Python 3.11, PostgreSQL 16 с pgvector и Ollama. На Windows:

```powershell
git clone https://github.com/laimen835/mangoflow-ai-qwen3-4b.git
cd mangoflow-ai-qwen3-4b
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-local.txt
Copy-Item .env.example .env.local
```

Локально настроить DATABASE_URL и параметры доступа в `.env.local`. Для контейнера БД
задать POSTGRES_PASSWORD в окружении процесса, затем `docker compose up -d db`.
DATABASE_URL должен соответствовать выбранному локальному пользователю/паролю;
не коммитить этот файл. Порт БД в шаблоне доступен только с этого компьютера.

В Ollama должны быть установлены Nomic и та же Qwen3 4B, что указана в
`model-version.json`. Имя `qwen3:4b-instruct` само по себе не гарантирует
совпадение весов с другим похожим тегом. Для точного импорта проверенного GGUF:

```powershell
ollama pull nomic-embed-text
# Поместить GGUF с SHA256 из model-version.json/model_artifact_sha256 в корень clone:
ollama create qwen3:4b-instruct -f Modelfile.qwen3-4b
.\.venv\Scripts\python.exe -m alembic upgrade head
.\run-local.ps1
```

Открыть http://127.0.0.1:8000/widget/demo.html. Ключ OPENAI_API_KEY в примере —
публичный не секретный маркер для локального Ollama, внешний OpenAI API не используется.
Собственный администраторский ключ задаётся только локально.

**Индекс знаний и веса не входят в Git.** Пустая БД не воспроизводит ответы
демонстрации. Проверенный снимок знаний передаётся владельцем отдельно без личных
диалогов либо создаётся штатными скриптами ingest после настройки профиля индекса.
Не снимать карантин документов ради наполнения базы. Векторный профиль — Nomic 768;
нельзя смешивать его с другими размерностями/префиксами.

Чистая установка на другой машине в рамках передачи не проверялась. Рабочая локальная
версия и публичный чат проверены. Некоторые экспериментальные CLI содержат guards
и исторические пути; прежде чем запускать их, адаптировать выделенные тестовые пути,
не отключая ограничения на пользовательскую БД.

## Проверки и ограничения

Модели сравнивались на 60 вопросах каждая. 4B выбрана за более осторожное поведение;
это не утверждение, что все ответы верны. Подробности — в отчёте сравнения.
Известны ошибки поиска, выбора области действия источника, шаблонных маршрутов
и коротких уточнений; платформа организаций/RLS не реализована.
Исторический полный pytest: 278 passed, 1 skipped, 1 известный failed
`test_focus_keeps_scholarship_source_and_removes_unrelated`; не скрывать этот сбой.

Публичный пример: https://grudgingly-innovative-pinscher.cloudpub.ru/widget/demo.html
Он работает через компьютер владельца, пока запущены сервисы и туннель; GitHub хранит
исходники, а не сервер RAG. Полный внутренний API нельзя выставлять в интернет:
для публикации используется только ограниченный гостевой шлюз.

Секреты, `.env.local`, личные беседы, дампы, скачанные оригиналы, OCR-кэш, журналы,
модели и приватные настройки туннелей в этот репозиторий не включены.
