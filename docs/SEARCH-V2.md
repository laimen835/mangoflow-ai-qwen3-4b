# Поиск знаний: эксперимент и эксплуатация

Состояние на 08.11.2026: активен `legacy-v1`. Кандидат `nomic-search-v2` построен отдельно, но **не прошёл условия включения**. Qwen3 4B, интерфейс и формат событий чата сохранены. Публичный шлюз отключён.

## Что доступно

- Уточнения используют предыдущие вопросы пользователя, сохраняя коды, годы и тему. Самостоятельные вопросы не получают факты из ответов модели.
- Различаются уточнение, отсутствие подтверждённого факта и техническая недоступность поиска. Общая официальная страница явно обозначается как направление проверки, а не доказательство.
- Частичный ответ должен содержать подтверждённую часть и отдельно недостающие сведения. Контакты, директор и проверенные расписания используют прежние точные обработчики.
- Список источников ограничен фрагментами, действительно вошедшими в контекст. Баллы ранжирования не являются вероятностью правильного ответа.

Кандидат объединяет векторный и полнотекстовый поиск, использует лексические совпадения как дополнительный сигнал, затем локально ранжирует до 20 кандидатов и возвращает до четырёх разных фрагментов. При недоступности reranker действует гибридный режим с диагностикой причины. Тестовые документы исключены общей политикой поиска.

Для Nomic введены разные префиксы `search_query: ` и `search_document: ` согласно [карточке модели](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5). Они применяются только в новом профиле. Старые векторы не перезаписываются при построении кандидата.

## Установка и проверка

Из корня репозитория в PowerShell:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-local.txt
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m scripts.setup_reranker
.venv/Scripts/python.exe -m scripts.search_index status
```

`setup_reranker` скачивает ONNX AVX2 и токенизатор из закреплённой ревизии `1427fd652930e4ba29e8149678df786c240d8825` модели `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`. Файлы и SHA256 manifest находятся в `D:/Codex-RAG-runtime/models/reranker-mmarco-avx2` (настраивается `RERANKER_DIRECTORY`). При обработке вопросов загрузок из интернета нет. Используется CPUExecutionProvider, три вычислительных потока.

На исходной базе без standby команда `python -m scripts.search_index build` строит кандидат, сохраняя активный индекс. Повторное построение поверх существующего standby намеренно запрещено. Перед миграцией текущего экземпляра сохранён отдельный pg_dump на диске D.

Профиль в `retrieval_index_state` хранит модель, digest, размерность, префиксы и версию подготовки. Загрузка материалов заполняет оба профиля. Пропуск неизменившегося текста учитывает fingerprint профиля и параметры разбиения, поэтому смена подготовки требует переиндексации даже при том же содержимом.

## Защищённая диагностика

`POST /api/v1/admin/search/debug`, заголовок `X-Admin-Key` из локального окружения:

```json
{"query":"А какие документы нужны?","index_slot":"candidate","history":[{"role":"user","content":"Как поступить в СПК?"}]}
```

Ответ содержит самостоятельный запрос, кандидатов, исходные и итоговые оценки, причины исключения и задержки. Для действующего индекса укажите `active`. Без ключа возвращается 401. Маршрут не доступен через публичный шлюз. Не размещайте ключ в примерах, URL или браузерном коде.

В `usage` чата добавлены `retrieval_status`, `search_ms`, `reranker_status`, `search_stages_ms`; обязательные поля и NDJSON-события не менялись. Точные ответы из структурированной базы могут обходить RAG, как прежде.

## Проверка и переключение

`tests/eval/search_cases.json` содержит замороженные 80 вопросов: 60 с адресом и точным фрагментом, 20 без достаточных сведений; в каждой половине 30/10. Порог выбран только по настройке, затем проверен на контроле. Это проверка извлечения фрагментов существующего корпуса, а не независимая оценка всех фактов сайта. Перефразирования одних фактов присутствуют в обеих половинах; для следующего эксперимента нужен новый контрольный набор с разделением также по фактам.

```powershell
.venv/Scripts/python.exe -m scripts.capture_search_baseline
.venv/Scripts/python.exe -m scripts.evaluate_search
.venv/Scripts/python.exe -m scripts.evaluate_missing
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m scripts.evaluate_quality
.venv/Scripts/python.exe -m scripts.evaluate_guardrails
```

Сначала сохраняйте прежние отчёты: эти команды записывают результаты в `logs/`. `capture_search_baseline` нужно запускать до изменения поведения приложения, чтобы получить настоящий исходный уровень. Генератор набора использует локальный снимок `work/search-corpus.json`; не пересоздавайте контроль после просмотра ошибок.

Условия включения: прирост Recall@4 на контроле не менее 10 п.п., отсутствие роста неподтверждённых ответов, прогретый p95 поиска не более 3000 мс и проверка регрессий. После отдельной фактической проверки отчёт должен явно содержать `activation_approved: true`, успешный `retrieval_gate_passed`, проверенный полный профиль и актуальный отпечаток корпуса. CLI отклоняет непроверенный или устаревший отчёт. Текущий отчёт содержит **false**; переключать кандидат нельзя.

После успешной будущей проверки оператор кратко останавливает API, выполняет `python -m scripts.search_index swap` и запускает API снова. Векторы и профили меняются одной транзакцией. Предыдущий индекс остаётся standby; обратная команда `swap` во время остановки возвращает его. Обмен и обратное восстановление проверены в откатываемой интеграционной транзакции. Для текущего неудачного кандидата производственного переключения не было.

Порог raw logit: −4,667626. Он не является процентом достоверности. Результат не разрешает включение. Оставшиеся проблемы: отбор коротких фактов из длинных фрагментов, конкуренция расписаний с общими сведениями, калибровка отказа и время обработки CPU. Повторная настройка должна использовать новые независимые контрольные вопросы; текущий контроль уже просмотрен.

Регрессии: 66 тестов прошли; 60 сценариев чата выполнены, 59 автоматически приняты. В сценарии 47 ответ об академии подтверждён официальным положением PDF, но проверка ожидала адрес общей страницы; исходное отклонение сохранено. Три синтетические проверки противоречий, инструкций внутри документа и отсутствующей цены прошли. Они не добавлялись в базу. В 20 ответах кандидата на вопросы без сведений при ручной проверке не обнаружено новых выдуманных фактов; это ограниченная проверка, не общая гарантия.

Полные локальные отчёты находятся рядом с проектом в `outputs/search-v2/`; базы, пароли, модели и журналы в Git не включены.
