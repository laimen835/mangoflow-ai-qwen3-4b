## Источники и загрузка

- В стипендиальном снимке две ссылки дали 404. Проверены только отрывки
  страниц 3–5 положения о материальной помощи с годом 2025 на обложке;
  актуальность на сегодня и рублёвые ставки не подтверждены. Другие блоки
  не допускать автоматически. Вопрос о том, кто принимает решение о помощи,
  в пилоте остался частичным: пропуск прямого пункта 4.3.
- Исторический 20-страничный скан превысил старый OCR-лимит 12 страниц.
  Нельзя молча считать усечённое извлечение полным. Есть лимиты размера,
  страниц и символов, битые/пустые страницы, непрочитанные таблицы.
- DOC/XLS не читаются как HTML, требуют конвертации. DOCX/XLSX проверялись
  также синтетически; это не гарантия всех реальных документов и формул.
- Правило review.scope=spo_confirmed создано для тематического СПО-пилота.
  При расширении на институты нужно явное проектирование применимости,
  а не массовое присваивание этой метки.

## Диалог и UI

- Перефразирование проверяет цитаты/числа/часть имён/оговорок лексически:
  это не доказательство смыслового равенства. При сомнении сохранять оригинал.
- Writing-задачи ограничены распознаваемыми формулировками и 2400 символами,
  max_tokens=500 может оборвать результат (есть предупреждение). Возможны
  неидеальные тон/формулировки. Перевод пользовательских [n] сейчас может
  быть отклонён консервативной проверкой ссылок.
- Новые задачи дают status→done, без постепенного вывода токенов. Не обещать
  одинаковое время первого текста со старым streaming RAG.
- Утверждение в интерфейсе «данные остаются на компьютере» исторически локальное:
  при доступе через CloudPub запросы идут через провайдера туннеля, а в облачном
  варианте обработка выполняется на VM. Нужна корректная подпись режима.
- Визуальная QA нового брендинга на ПК/мобильном/200% не завершена из-за сбоя
  инструмента браузера; HTTP и asset hash не проверяют расположение элементов.

## Эксплуатация

- При подготовке этой передачи соединение с локальной БД было отклонено.
  Это наблюдение об остановленном/недоступном сервисе, не доказательство потери
  базы. Не восстанавливать дамп поверх данных только из-за ConnectionRefused.
- Старый README/start-local предполагают порт8000 и `.venv` в текущем корне.
  В worktree используется Python исходного checkout, API8004 и gateway8000.
  Путаница может запустить не ту версию или создать proxy-петлю.
- CloudPub `clo.exe run` не обеспечивает автозапуск API/БД/Ollama, не гарантирует
  вечный адрес и работает только при доступном ПК/интернете. Выключение экрана
  допустимо; сон/гибернация прерывают локальный хостинг.
- Guest session mapping/лимиты находятся в памяти. После рестарта шлюза
  публичная история не сопоставится с прежней, хотя записи БД сохраняются.
  Полноценной авторизации и промышленного multi-worker session store нет.
- Облачная CPU-проба: первые тексты ~32–54с, полные ответы ~35–106с на шести
  вопросах; замер диагностики повторов 84,03/32,012с, CPU ~94–97%, steal~0.
  Это не p95 и не гарантия под нагрузкой. Увеличение timeout не улучшает факты.
- Код локального пилота и облака разошёлся. Не считать наличие логотипа в
  CloudPub доказательством обновления отдельной VM. Новые ресурсы и тарифы
  не менять без соответствующей задачи владельца.
- Исходные Windows-скрипты/приватные адаптеры привязаны к путям D. Git worktree
  зависит от исходного репозитория. Перенос одной папки app недостаточен для
  переноса БД, моделей, конфигурации, файлов и Python-окружения.
