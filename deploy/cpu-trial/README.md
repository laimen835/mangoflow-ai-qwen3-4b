# Проба CPU-сервера

Цель: проверить ту же Qwen3 4B и существующую базу на 4 vCPU / 16 ГБ / 80 ГБ.
Тариф, доступность CPU и минимальное пополнение проверяются в кабинете перед запуском.
Разрешён короткий пробный запуск; продолжение аренды на неделю требует решения после замеров.

## Что готово

`python -m scripts.prepare_cpu_trial --output D:/Codex-RAG-runtime/cpu-trial-UNIQUE`
создаёт локальные архивы кода, данных, точных файлов двух действующих моделей,
согласованный pg_dump и manifest.json с контрольными суммами.

Дамп содержит историю диалогов проекта. Папка является приватной копией для сервера владельца,
а не публичным релизом. Пароли исходного ПК, .env, журналы, Git, ngrok и остальные модели не включены.

## Требования к серверу

Обычный Ubuntu Server 24.04 LTS x86-64, SSH и Docker Engine с Compose plugin.
Образ «ИИ-ассистент» провайдера не нужен: он может ограничивать конфигурацию или добавлять другие модели.
Использовать официальный способ установки Docker; установку и сборку выполнить до замеров.
Сборка Linux-образа и запуск в облаке ещё не проверены на стадии локального экспорта.

## Восстановление на новой пробной машине

Загрузить архивы в приватный каталог, проверить SHA-256 по manifest.json, распаковать code.tar.gz
в каталог приложения. Следующие команды выполняются только на новой пробной машине.

```sh
cd /path/to/app/deploy/cpu-trial
umask 077
python3 - <<'PY'
from pathlib import Path
import secrets
path = Path('trial.env')
with path.open('x') as stream:
    stream.write('POSTGRES_PASSWORD='+secrets.token_hex(32)+'\n')
    stream.write('ADMIN_API_KEY='+secrets.token_hex(32)+'\n')
path.chmod(0o600)
PY
mkdir -p state/data state/logs state/ollama
tar -xzf /path/to/export/data.tar.gz -C state/data
tar -xf /path/to/export/models.tar -C state/ollama
sudo chown -R 10001:10001 state/data state/logs
docker compose --env-file trial.env -f compose.json up -d db ollama
```

Дождаться healthy у базы. Восстановить дамп ровно один раз в пустую БД:

```sh
docker compose --env-file trial.env -f compose.json exec -T db \
  pg_restore --exit-on-error --no-owner --no-privileges -U postgres -d rag < /path/to/export/database.dump
docker compose --env-file trial.env -f compose.json up -d --build api
curl --fail http://127.0.0.1:8000/ready
```

Сверить оба digest моделей с manifest.json. Проверить содержимое базы и активный профиль индекса.
Автоиндексация выключена для честного измерения скорости чата.
Точные зависимости берутся из текущих requirements; если сборка не проходит, не менять их вслепую.

## Приватная проверка

С ПК владельца открыть SSH-туннель `8003:127.0.0.1:8000` к новому серверу.
Открыть http://127.0.0.1:8003/ и запустить `scripts/benchmark_cpu_trial.py`.
Полный API привязан к loopback сервера; PostgreSQL и Ollama не публикуются.
Публичный доступ на неделю настраивается отдельно через гостевой шлюз и HTTPS после проверки.

Первый ответ замерять отдельно от прогретых. Оценивать ответы, источники, время первого текста,
полное время и очередь. Быстрый ответ из карточки директора не доказывает скорость генерации LLM.

## Завершение пробы

Остановка контейнеров не прекращает оплату виртуальной машины.
В кабинете нужно остановить/удалить пробный сервер после согласования сохранения результатов.
У выключенного сервера могут оставаться списания за диск, IP и резервные копии.
Полное удаление ресурсов выполнять только после проверки локальной исходной копии и подтверждения владельца.
Длительность оплачиваемого теста считать от создания VM, включая установку и перенос.
